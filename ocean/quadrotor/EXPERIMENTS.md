## Before Running Anything

Use this as the preflight checklist for every GPU run:

1. Search this file for the scenario, changed knob, seed, and budget.
2. If an existing QDR row already answers the same question, do not rerun it.
3. If the new run is still needed, add a row with status `pending` before
   launching it.
4. Change one main variable unless the row explicitly says it is a combo or
   robustness check.
5. Evaluate with deterministic `mean` actions before calling the test passed.

Duplicate definition: same scenario, same main knob, same seed set, same
training budget, and same deterministic eval gate. Reruns are only evidence if
they fix a bug, increase statistical confidence, or test a deliberately changed
condition.

## Evaluation Rules

- Every non-trivial run gets a `QDR-###` ID before we treat its result as
  evidence.
- Use names like `<rung>_<change>_s<seed>` for single-seed runs and
  `<rung>_<change>_3seed` for small robustness checks.
- Record the hypothesis, exact non-default knobs, artifact path, deterministic
  checkpoint result, and verdict. Sampled eval and PPO HUD can be mentioned,
  but they do not decide whether a test passed.
- Before starting a similar run, search this file for the changed knob, seed,
  and scenario name.

- Deployment gate: deterministic `mean` action checkpoint eval.
- Diagnostic only: sampled action eval and the PPO training HUD.
- Standard eval for the current rung:
